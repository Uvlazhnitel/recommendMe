# Проверка качества подборки

Это чеклист персонального прототипа, не автоматическая метрика точности. Проверяемые данные и мнение владельца фиксируются отдельно. Если исходный ответ или обратная связь отсутствуют, результат проверки — «неизвестно», а не положительная оценка.

## Автоматические проверки

- Все ID принадлежат проверенному набору кандидатов; нет дублей, TV, короткого метра и неизвестной длительности.
- Просмотренное, включая NULL-оценки и историю без TMDB ID, исключено по актуальной SQLite.
- `not_interested` и 30-дневный период показов учитываются; старый исторический `rejected` не становится вечным запретом.
- ID/оценки структурированных свидетельств соответствуют переданному контексту и актуальной базе. Это не доказывает истинность свободного объяснения.
- Новые, изменённые и очищенные оценки присутствуют в следующем входе; NULL не равен 0. Отказ/API-ошибка не заменяются случайной выдачей.
- Соблюдены ограничения размера контекста и запросов. Usage берётся из ответа, копии одного артефакта повторно не суммируются.
- Явное сохранение транзакционно и идемпотентно; пользовательские оценки не меняются.

Основной набор проверок: `npm run test:db`. Для подготовки существующего входа без оплаты:

```sh
npm run recommendations:rank -- --input data/candidates.json --dry-run
npm run taste:status
npm run recommendations:history
```

Dry-run ничего не записывает и не вызывает API. Новые live-эксперименты выполняются только по явному решению владельца. Не пересоздавать профиль из-за отсутствующего отчёта.

## Человеческая оценка

- **Персональная связь:** объяснение опирается на реальные оценки и подтверждённые особенности кандидата, а не только общий жанр или сюжетный мотив.
- **Контрпримеры:** низкие оценки и контрасты используются содержательно; причины личных оценок не объявляются установленными фактами.
- **Риск:** `possible_mismatch` конкретен либо честно называет неопределённость; недостаток не придуман ради поля.
- **Широта:** не повторяются одинаковые аргументы под разными названиями; другие стороны вкуса не теряются. Жанровые квоты не обязательны.
- **Неочевидность:** малоизвестность не является достоинством или недостатком сама по себе; нужны основания личного соответствия.
- **Интерес и результат:** общая реакция на подборку не заменяет индивидуальный интерес и оценку после просмотра.

Повторы ID/жанров/режиссёров и частоты свидетельств можно описывать числами. Они не измеряют художественное качество или вероятность оценки ≥80. Частоты входного профиля нельзя выдавать за частоты отсутствующего ответа модели. Долю действительно полученных оценок ≥80 допустимо описывать только после просмотра, с числом наблюдений и без названия «прогнозируемая точность».

## Пустой шаблон обратной связи

Скопировать в приватный файл внутри `data/`; не заполнять за владельца и не коммитить реальные ответы.

```text
Дата / result_id:
Модель:
Usage и его источник (если нет — неизвестно):
Файл исходного результата:
Общая реакция владельца на подборку:

Фильм / год / TMDB ID:
Интерес до просмотра: интересно / не уверен / неинтересно / неизвестно
Какие реальные оценки поддерживают why_fit:
Связь убедительна / слишком общая / неизвестно; замечания:
Риск конкретен / общая оговорка / неподтверждён / неизвестно:
Есть ли вымышленные факты или причины оценок:
Повторяются ли аргументы других рекомендаций:

Просмотрен: да / нет / неизвестно
Личная оценка после просмотра: целое 0–100 / NULL (не оценено)
Причина расхождения с ожиданием, если владелец хочет её указать:
```

Если нужен платный эксперимент, сначала сформулировать вопрос, недостаток имеющихся данных и точное число новых запросов. Сравнение моделей, дополнительные методы разнообразия и статистические рекомендатели — отдельные будущие решения, а не обязательное продолжение аудита.
