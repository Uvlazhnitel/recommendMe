# Personal Movie Recommender

Личное веб-приложение для рекомендаций полнометражного кино по истории оценок владельца. Цель будущего рекомендателя — находить фильмы с личной оценкой 80/100 и выше; это не гарантия результата.

**Статус на 2026-10-25:** технический фундамент фазы 1 проверен. Импорт Letterboxd и обогащение TMDB работают. Фаза 2, AI-профиль, рекомендации и пользовательские экраны ещё не реализованы.

## Локальный запуск

Нужны Node.js ≥22 и npm; проверено на Node.js 26.11.1 / npm 11.20.0. Проект использует Next.js App Router, TypeScript и better-sqlite3 без ORM.

```sh
npm install
# Только при отсутствии своего .env.local:
cp -n .env.example .env.local
npm run db:init
npm run db:check
npm run dev
```

Открыть [localhost:3000](http://localhost:3000). Пока доступна стартовая страница Movie Recommender и `GET /api/health`. Dev и production-сервер по умолчанию слушают только 127.0.0.1.

Для production-запуска локально:

```sh
npm run build
npm run start
```

SQLite по умолчанию хранится в `data/movies.sqlite`, отдельно от сборки. `DATABASE_PATH` может быть абсолютным или относительным от корня проекта. `db:init` применяет миграции без очистки данных; запуск приложения сам миграции не выполняет.

## Первоначальные данные

Личные исходники размещаются в `data/import/watched(6).csv` и `data/import/ratings(6).csv`. Их нет в Git. Команда разработчика для первоначального заполнения:

```sh
npm run seed:letterboxd
# Либо указать пути:
npm run seed:letterboxd -- --watched /path/watched.csv --ratings /path/ratings.csv
```

Повторный запуск не создаёт дубликаты и не заменяет существующие персональные записи, включая ручные и очищенные оценки. `0` — реальная оценка, `NULL` — отсутствие оценки. Даты двух CSV хранятся отдельно и не считаются подтверждённой датой просмотра.

Импорт сохраняет всю историю, включая короткометражки и произведения, не найденные в Movie Search. В будущем рекомендателе будут допустимы только фильмы с подтверждённой длительностью от 60 минут.

## TMDB

Настроить настоящий API key v3 в серверной переменной `TMDB_API_KEY` в `.env.local`. Ключ в Git и чат не добавлять. Поиск и метаданные используют английский `en-US`; названия, годы и URI Letterboxd остаются неизменными.

```sh
npm run tmdb:enrich -- --dry-run --limit 10
npm run tmdb:enrich -- --limit 10
npm run tmdb:enrich
```

Сначала проверить кандидатов dry-run: он не меняет SQLite. Обычный запуск создаёт резервную копию, применяет миграции и сохраняет прогресс по каждому произведению. Повторный запуск пропускает успешно обработанные и нерешённые записи. Для осознанной повторной проверки нерешённых есть `--retry-unresolved`; эта команда не исправляет неоднозначности автоматически.

Текущая личная база: **830 просмотров, 519 оценок, 311 без оценки**. С TMDB сопоставлены **756** произведений; **33** неоднозначны, **41** без точного соответствия. Все 830 сохранены. Отсутствие ID не означает отсутствия произведения в TMDB. Отчёты находятся в `data/import-reports/` и `data/tmdb-reports/`, бэкапы — в `data/backups/`.

## Проверки

```sh
npm run test:db
npm run lint
npm run typecheck
npm run build
```

Тесты используют синтетические CSV, временные базы и HTTP-моки, без реального TMDB/OpenAI. В комплект входит сквозная проверка CSV → SQLite → TMDB → повторный импорт с сохранением оценок и метаданных. Отдельная live-проверка TMDB и аудит личных данных зафиксированы в PROGRESS.md.
