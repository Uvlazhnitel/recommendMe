# PROJECT_SPEC.md — требования к MVP

**Версия:** 1.0 (зафиксирована 2026-10-25)  
**Тип:** личный, некоммерческий проект для одного пользователя.

## 1. Зачем делаем

Создать приложение, которое рекомендует **полнометражные фильмы**, основываясь на личных оценках владельца, с целью находить кино, которому он поставит **≥80/100 (порог 4★/5 Letterboxd)**.

**Приоритет:** качество и убедительность подбора, максимально близкое к тому, как ChatGPT рекомендует фильмы после анализа всей истории, а не максимальная сложность технологий. Совпадение с популярными жанрами недостаточно: нужно учитывать и низкие, и высокие оценки, контрасты вкуса, реальные сведения о фильмах.

Нет обещания, что каждая рекомендация получит 80+. Не показывать псевдонаучных процентов вероятности без оценки и калибровки.

## 2. Принятые решения

| Область | Решение |
| --- | --- |
| Пользователь | Только владелец; не нужны аккаунты и мультипользовательность. |
| Где работает | Домашний сервер, веб-доступ с телефона и компьютера. Начать с локальной сети. |
| Тип контента | Рекомендовать только полнометражные фильмы, не сериалы и не короткий метр. |
| Первая загрузка | **Backend-скрипт** один раз читает два предоставленных CSV Letterboxd. UI импорта отсутствует. |
| Дальше | Поиск фильма через TMDB, ручное добавление/редактирование оценок 0–100 и статуса просмотра. |
| Каталог | TMDB (описания, ID, постеры, год, длительность и т. д.). |
| Рекомендации | Сохранённый вкусовой профиль + LLM + TMDB-проверка кандидатов + финальный LLM-выбор. |
| Количество | Целевой результат — пять фильмов, но лучше меньше, чем фиктивные/слабые варианты. |
| Неизвестное кино | Не запрещено. Пропускать случайные, слабо подтверждённые находки. |
| Данные | SQLite и бэкап; без потери истории при обновлениях приложения. |
| Технологии | Next.js/TypeScript, SQLite, TMDB API, LLM API, Docker Compose. |

## 3. Реальные исходные данные

Исходные файлы (в комплект документации **не включены**): `ratings(6).csv` и `watched(6).csv`.

- `watched(6).csv`: **830 уникальных** записей, столбцы `Date`, `Name`, `Year`, `Letterboxd URI`.
- `ratings(6).csv`: **519 уникальных** записей, столбцы `Date`, `Name`, `Year`, `Letterboxd URI`, `Rating`.
- Все 519 оценённых записей входят в `watched`; **311 просмотрены, но не оценены**.
- **245** оценок ≥4★; средняя оценка ≈3,70★. Это описательная статистика, а не измерение качества модели.
- Для старых оценок используем `rating_100 = original_stars × 20`, сохраняя исходные звёзды. Для новых — любое целое 0..100.
- `NULL` в оценке означает отсутствие оценки. `0` означает реальную оценку 0/100. Они принципиально различаются.
- Нельзя по столбцу `Date` молча делать вывод об истинной дате просмотра: он может относиться к записи/оценке.
- Все старые просмотренные записи исключаются из рекомендаций, **включая без оценки**.
- Не весь старый экспорт обязательно относится к полнометражным фильмам; исходные записи нужно сохранить, а фильтры рекомендаций применять отдельно.

## 4. Пользовательские сценарии

### A. Получить подборку

1. Открыть раздел **Рекомендации**.
2. Нажать **«Подобрать фильмы»**.
3. Увидеть до пяти карточек: постер, название, год, жанры/длительность, **почему мне может понравиться**, **что может не подойти**.
4. Увидеть корректные ссылки на TMDB (при наличии) и возможность открыть детали.
5. Нажать **«Ещё рекомендации»** или **«Неинтересно»**. Отклонённый вариант не предлагать вновь до явного сброса, но **не** приравнивать отклонение к низкой оценке.

### B. Оценить новый фильм

1. Открыть **«Оценить фильм»**, найти через TMDB по названию.
2. Выбрать правильный фильм, отметить просмотренным, выставить оценку **от 0 до 100**.
3. Сохранить. При следующей подборке фильм не рекомендуется, новая оценка учитывается при ранжировании.
4. Разрешить отмечать просмотр без оценки.

### C. Просмотреть и исправить историю

1. Открыть **«Библиотека»**.
2. Найти импортированный или добавленный фильм, увидеть просмотр/оценку.
3. Изменить или удалить **свою оценку**. Не удалять сам факт просмотра автоматически.
4. Убедиться, что изменения переживают перезагрузку браузера и перезапуск приложения.

## 5. Три экрана — и только они

1. **Рекомендации**: подборка и обратная связь «Неинтересно».
2. **Оценить фильм**: поиск и ввод оценки; можно открыть тот же вид из библиотеки.
3. **Библиотека**: список просмотренного, поиск и редактирование.

Адаптивная компоновка под смартфон и десктоп. Без необязательной анимации, личных кабинетов и сложной кастомизации. Понятные состояния «загружается», «ошибка», «нет результатов».

## 6. Минимальные функциональные требования

- Исходная база заполняется разовым скриптом; без публичного маршрута импорта.
- Один фильм не размножается из-за повторной оценки/открытия. Сопоставление с TMDB опирается на ID и проверенные год/название, не только на текст названия.
- Импортированные и ручные оценки различимы по источнику; исходный Letterboxd URL не теряется.
- Проверка нового фильма: правильный TMDB ID, формат `movie`; в рекомендателе длительность по умолчанию **от 60 минут**, чтобы убрать короткометражки. При неопределённой длительности сначала уточнить/не включать в автоматическую выдачу.
- В выдаче нет просмотренных, отклонённых, дублей, сериалов, короткометражек или несуществующих названий.
- Низкие личные оценки участвуют в построении вкусового профиля наравне с высокими.
- Новая или изменённая оценка влияет на **следующий** запрос через свежие данные, даже когда сводный текстовый профиль обновляется периодически.
- При сбое TMDB/LLM не изображать успешную генерацию; возвращать понятную ошибку.
- Личные данные сохраняются в постоянном SQLite-хранилище, отдельном от образа Docker.

## 7. Что исключено из MVP

- Импорт/синхронизация через интерфейс, API Letterboxd, поддержка многократных ZIP-загрузок.
- Собственная обучаемая ML-модель, MovieLens, bir.mov, Tag Genome, embeddings, векторная БД.
- AI-чат и свободный диалог, сложные режимы жанра/настроения, персональная аналитика, социальные функции, уведомления.
- Регистрация, роли, облачная синхронизация, native-приложения, публичный доступ через интернет.
- Требование обучить LLM/дообучать нейросеть после каждой оценки. «Учиться» для MVP означает **актуализировать данные для следующей рекомендации**.

Эти идеи могут вернуться **только после использования MVP и обнаружения конкретной проблемы**.

## 8. Критерий «MVP готов»

- На домашнем сервере доступны все три экрана с телефона и ПК.
- История Letterboxd загружена скриптом: исходные счётчики воспроизводятся, ошибки сопоставления видны и не подменяются угадыванием.
- Вручную найден фильм, установлен просмотр/оценка, изменена оценка; данные пережили перезапуск контейнера.
- Получены реальные, неповторяющиеся рекомендации полнометражного кино; карточки содержат конкретные аргументы с опорой на индивидуальный вкус, а не общие комплименты.
- Проверено исключение всех просмотренных и отклонённых; новая оценка учитывается в следующем подборе.
- Есть базовые тесты, ограничение расхода LLM, безопасное хранение API-ключей и проверенный путь резервного копирования.
- Владелец просмотрел **несколько подборок** и считает их достаточно полезными, чтобы пользоваться приложением. Нельзя подменять это показателем, придуманным моделью.
