## Подфаза 1.2 — схема SQLite — 2026-10-25

- [x] Созданы четыре STRICT-таблицы: `movies`, `user_movies`, `recommendations`, `taste_profile`. Прикладных данных в рабочую базу не добавляли.
- [x] Уникальны известные `tmdb_id` и `letterboxd_uri`; несколько NULL и одинаковые название/год допустимы. Для `tv` TMDB movie ID запрещён.
- [x] Персональная запись одна на фильм (`movie_id` — PK/FK). Рейтинг — INTEGER 0–100 или NULL; исходные звёзды — 0–5 с шагом 0,5; булевы поля — 0/1. Просмотр, рейтинг, отклонение независимы.
- [x] История рекомендаций допускает повторные показы. Глобальное скрытие (`user_movies.not_interested`) и отклонение показа (`recommendations.rejected`) хранятся отдельно; пользовательская операция отклонения пока не реализована.
- [x] Один JSON-профиль (`id=1`), проверка JSON; `genres_json` — массив или NULL. Создание персональной записи и профиля получает UTC timestamps; триггеры обновляют `updated_at` при изменении содержательных полей, сохраняя `created_at`. `watched_at` не заполняется по `letterboxd_date`.
- [x] На каждом соединении включены внешние ключи; удаление связанных фильмов ограничено RESTRICT. Для показов добавлен индекс `(movie_id, recommended_at)`.
- [x] Первая SQL-миграция `migrations/001_initial.sql`, исполнитель `src/lib/migrations.ts`, CLI `scripts/db-init.ts`, команда `npm run db:init`. Схема версионируется `PRAGMA user_version`; все ожидающие миграции выполняются в одной IMMEDIATE-транзакции с откатом при ошибке. Неизвестная более новая версия отклоняется. Открытие БД и health не запускают миграции.
- [x] Все автоматические тесты работают с временными файлами SQLite; прежний тест относительного пути больше не открывает рабочую базу.

**Принятые решения:** по текущему заданию вместо прежних `recommendation_batches` / `recommendation_items` используется одна `recommendations`, описание согласовано в DATA_AND_DEPLOYMENT.md. ## Подфаза 1.1 — создание проекта — 2026-10-25

- [x] Минимальный Next.js App Router + TypeScript (strict), npm и ESLint; стартовая страница Movie Recommender, обычный CSS.
- [x] SQLite через `better-sqlite3`, отдельный Node-only модуль `src/lib/db.ts`; ленивое открытие, создание родительского каталога и явное закрытие соединения вызывающим кодом.
- [x] `DATABASE_PATH`: абсолютный либо относительно корня проекта; по умолчанию `./data/movies.sqlite`. Пустой путь и `:memory:` отклоняются. Основная база не содержит таблиц.
- [x] `.env.example`: DATABASE_PATH, TMDB_API_KEY, OPENAI_API_KEY, OPENAI_MODEL. Внешние ключи необязательны; интеграций и SDK нет. CLI загружает окружение через `@next/env`; значения не экспортируются в браузер. Health route помечен `server-only`, модуль БД использует Node.js fs.
- [x] Динамический `GET /api/health`: SELECT 1, HTTP 200/503, Cache-Control: no-store, без раскрытия путей и внутренних исключений.
- [x] Команды `dev`, `build`, `start`, `typecheck`, `lint`, `db:check`, `test:db`; зависимости зафиксированы package-lock.json.
