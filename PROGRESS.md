### Принятые правила и реализация

- Миграция 004 добавляет nullable recommendations.result_id и уникальный частичный индекс (result_id,movie_id). Старые строки/четыре таблицы сохраняются, дополнительных таблиц нет. В рабочую базу миграция автоматически не применялась: она остаётся на версии 3 до явного записывающего действия владельца. Новые read-only команды работают со схемами 3/4.
- `src/lib/recommendation-memory.ts`: общий offline-механизм preview/record, SQLite backup, отклонение и чтение истории. Запись — одна IMMEDIATE-транзакция; повтор result_id не меняет строки, даты или объяснения, включая частично сохранённый набор. При SQL-ошибке все вставки movies/recommendations откатываются. Два независимых процесса не записывают один фильм одновременно: внутри транзакции перечитываются состояния и недавние показы.
- Выбранные ID обязаны принадлежать валидированному набору 2.2, пройти проверки типа/длительности и для AI-результата — свидетельств 2.3. Непосредственно перед записью заново проверяются просмотр, not_interested, недавние показы и оценки свидетельств. Ставшие недопустимыми элементы пропускаются с причинами.
- Новые movies получают доступные проверенные метаданные; отсутствующие URI Letterboxd/характеристики остаются NULL. tmdb_attempted_at остаётся NULL: при сохранении TMDB не вызывался. Существующие фильмы по TMDB ID используются без перезаписи. Для рекомендации персональная строка не создаётся, оценки/Letterboxd не меняются.
- `recommendations:rank --input … --live` сохраняет read-only поведение. Только явный --live --save разрешает запись; недопустимые сочетания отвергаются до открытия базы для записи. Backup создаётся до платного запроса, миграция/запись — после успешного ответа. Нет открытой SQL-транзакции во время HTTP. Ошибка backup/непригодная к записи связь предотвращает API-вызов.
- Успешный результат получает UUID result_id и generated_at UTC. JSON содержит save.saved_count/already_saved_count/would_save_count/skipped. При ошибке записи результат, UUID и usage остаются в выводе, save.status=error, CLI код 1; LLM автоматически не повторяется. Можно повторить запись через record --result без API.
- `src/lib/recommendation-policy.ts`: период RECOMMENDATION_REPEAT_DAYS=30, ровно 30×24 часа от последнего сохранённого показа. Общий фильтр 2.2/2.3 учитывает recently_recommended до финального платного отбора и перед выдачей/записью, включая старые файлы кандидатов. Фильтр не ослабляется; меньше пяти или пустой результат допускаются с диагностикой. На точной границе 30 дней фильм снова допустим. not_interested блокирует независимо от даты.
- `recommendations:record --input … --tmdb-ids …`: по умолчанию только preview, запись только с --save, сетевых вызовов нет. Ключ ручной операции — хеш отсортированного набора ID, повтор не дублирует показы. Для прежних подборок объяснения NULL, дата — момент явного внесения, не неизвестное точное время первоначального показа.
- Альтернативный --result принимает успешный сохранённый AI-результат, проверяет IDs/тексты/свидетельства, сохраняет настоящие объяснения/UUID; для старого результата без UUID используется стабильный хеш содержимого. --result и --tmdb-ids несовместимы; --save и --dry-run несовместимы. Backup новых записывающих CLI находится рядом с SQLite в backups/ (для рабочей базы — data/backups/).
- `recommendations:reject --tmdb-id …`: одна транзакция для user_movies.not_interested=1 и recommendations.rejected=1. При отсутствии персональной строки создаются watched=0/rating_100=NULL/source=none. Оценки/исходные звёзды/просмотр сохраняются. Повтор безопасен, сбой обновления истории откатывает и персональный флаг. Неизвестный локально ID отклоняется без TMDB-запроса.
- --undo снимает только текущий not_interested. Исторический rejected остаётся фактом прошлого отклонения; фильтры не используют его как вечный чёрный список. Период 30 дней после отмены продолжает действовать. recommendations:history выводит имя/год/TMDB ID/дату/оба признака и доступные объяснения, не зависит от файлов кандидатов.
- `src/lib/taste-refresh.ts` и taste:status: существующее сравнение с ratings_snapshot переиспользовано. Считаются добавленные/изменённые/очищенные оценки по итоговому состоянию, один фильм один раз; возврат к исходной оценке убирает отличие. NULL→0 и очистка учитываются, not_interested и просмотр без оценки — нет. Статусы current/stale/refresh_recommended, порог 10. В сводки кандидатов/ранжирования добавлен profile_refresh, прежние cache/profile_status сохранены.
- Рекомендация пересчёта показывает существующую `npm run taste:generate -- --live --force`. Автоматических платных обновлений, дополнительных моделей, проверочных API-вызовов и фоновых задач нет.
